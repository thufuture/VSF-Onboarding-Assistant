# P1 — Data model + migration + RBAC/scope nền tảng (chi tiết)

> Thuộc [ke-hoach-trien-khai-portal.md §5](../ke-hoach-trien-khai-portal.md) (P1), triển khai cụ thể các quyết định đã chốt ở [P0A.md](../P0A/P0A.md). Trước khi viết tài liệu này đã đọc trực tiếp code backend thật (`backend/src/model/`, `backend/src/api/dependencies.py`, `backend/alembic/`) — nhiều phần cần cho Portal **đã có sẵn**, không phải viết từ đầu.

## 0. Phát hiện quan trọng từ code thật — sửa lại giả định trước đó

Đọc code phát hiện 2 điểm lệch với giả định ở mục 3 [ke-hoach-trien-khai-portal.md](../ke-hoach-trien-khai-portal.md) và ở [P0A.md](../P0A/P0A.md); ghi nhận sửa ở đây, coi như bản cập nhật chính thức:

| Giả định trước đó | Thực tế trong code | Hệ quả |
|---|---|---|
| Role Portal gồm `EMPLOYEE`/`HR`/`ADMIN` | `backend/src/model/enums.py` → `UserRole = USER \| HR \| ADMIN` (đã tồn tại, có `CHECK` constraint qua `check_in()`) | Portal **dùng lại `USER`** cho vai trò "nhân viên" — không thêm role `EMPLOYEE` mới trong DB. Tài liệu vẫn gọi "Employee/Nhân viên" khi nói chuyện nghiệp vụ, nhưng giá trị lưu là `USER` |
| Thêm cột mới `users.primary_team_id` để biết nhân viên/HR thuộc phòng ban nào | `backend/src/model/team.py` + `team_member.py`: bảng `teams`/`team_members` **đã có sẵn** từ migration `0001_core.py`, dạng many-to-many (PK kép `team_id+user_id`). Đang được dùng ở `auth_service.department_name()` để nối tên nhiều phòng ban của 1 user | **Không thêm cột `primary_team_id`.** Portal tái dùng thẳng `team_members`. Quy tắc quyền viết theo kiểu `EXISTS (SELECT 1 FROM team_members WHERE team_id=:team_id AND user_id=:user_id)`, giống cách `auth_service.department_name` đang query. Nếu thực tế mỗi user Portal chỉ nên ở đúng 1 team, ràng buộc đó xử lý ở **tầng ứng dụng** (validate khi gán), không cần `UNIQUE` trên `team_members.user_id` vì có thể phá tính năng nhiều-phòng-ban đang dùng cho mục đích khác của chatbot |
| Enum trạng thái viết dạng `ENUM('A','B',...)` | `backend/src/model/enums.py`: dự án dùng `StrEnum` + `CHECK (column IN (...))` qua helper `check_in()`, **không dùng native Postgres ENUM type** | Mọi enum Portal (trạng thái `employee_tasks.status`, v.v.) viết theo đúng pattern `check_in()` này, thêm class `StrEnum` mới trong `enums.py` |

Không có bảng/model nào cho ticket, journey, task tồn tại sẵn — đây là phần hoàn toàn mới, đúng như dự đoán.

## 1. Việc cần làm

1. Thêm các `StrEnum` mới vào `backend/src/model/enums.py`: `EmployeeTaskStatus` (theo P0A mục 4, đã bỏ `NOT_APPLICABLE`/`WAITING_APPROVAL`), `TicketStatus` (nếu chưa có khái niệm tương đương — kiểm tra kỹ trước khi thêm, tránh trùng khái niệm ticket cũ nào đó nếu có ở nơi khác).
2. Tạo model SQLAlchemy mới trong `backend/src/model/` (mỗi bảng 1 file, theo đúng convention `Base`, `id_column()`, `created_at_column()`, `updated_at_column()`, `TimestampTZ` từ `base.py`):
   - `journey_template.py`, `journey_stage.py`, `task_template.py`, `task_dependency.py`
   - `employee_journey.py`, `employee_task.py`
   - `task_source_mapping.py` (nối task với document/version/section — dùng lại `Document`/`DocumentVersion`/`DocumentSection` đã có ở `model/document*.py`, không tạo lại)
   - `contact_channel.py`, `approved_link.py` (DRAFT/APPROVED theo §4.3 ke-hoach-portal-onboarding.md)
   - `ticket.py`, `ticket_message.py`
   - `content_gap.py`
3. Đăng ký model mới vào `backend/src/model/__init__.py` (theo đúng cách `TeamMember` đang được export).
4. Viết migration mới trong `backend/alembic/versions/` — **chạy `alembic heads` trước để biết revision hiện tại**, đặt tên theo văn phong đang có (`0001_core.py` → migration Portal có thể là `0002_portal_core.py`, nhưng số thật phụ thuộc còn migration nào khác đã thêm chưa từ lúc `master-plan.md` viết tới giờ).
5. Viết RBAC/scope dùng chung trong `backend/src/api/dependencies.py`:
   - Tái dùng `require_role(*roles)` đã có (không viết lại).
   - Thêm `require_team_scope(team_id_param: str)` hoặc tương đương — dependency kiểm tra user hiện tại (role HR) có thuộc `team_id` của resource đang truy cập không, dùng `EXISTS` như mục 0 đã nêu. Cần 1 hàm helper dùng chung, không lặp lại `EXISTS` ở từng router.
6. Viết 1 API mẫu (route bất kỳ, ví dụ `GET /portal/journeys` rỗng) áp dụng `require_role("USER","HR","ADMIN")` + `require_team_scope` để làm bằng chứng RBAC hoạt động, phục vụ Definition of Done.
7. Seed dữ liệu giả lập tối thiểu (1 team, vài user role USER/HR/ADMIN, gán vào `team_members`) — có thể mở rộng `backend/src/services/auth/seed.py` đang có sẵn thay vì viết seed script riêng.

## 3. RBAC/scope — chi tiết kỹ thuật

```python
# backend/src/api/dependencies.py — thêm mới, không sửa require_role đã có

async def require_team_scope(team_id: int, user: User, db: AsyncSession) -> None:
    """403 nếu user (role HR) không thuộc team_id đang truy cập. ADMIN luôn qua."""
    if user.role == UserRole.ADMIN:
        return
    exists = await db.scalar(
        select(TeamMember.team_id).where(TeamMember.team_id == team_id, TeamMember.user_id == user.id)
    )
    if exists is None:
        raise AuthError(403, "FORBIDDEN_TEAM_SCOPE", "auth.forbidden_team_scope")
```

Router mẫu áp dụng cả hai lớp:
```python
@router.get("/portal/journeys")
async def list_journeys(
    team_id: int,
    user: Annotated[User, Depends(require_role(UserRole.HR, UserRole.ADMIN))],
    db: Annotated[AsyncSession, Depends(get_db)],
):
    await require_team_scope(team_id, user, db)
    ...
```

## 4. Definition of Done — P1 xong khi nào

- [ ] Enum mới thêm vào `enums.py` theo đúng pattern `check_in()`, không dùng native ENUM.
- [ ] Toàn bộ model mới ở mục 2 tạo xong, export trong `model/__init__.py`.
- [ ] Migration mới chạy được (`alembic upgrade head` sạch), `alembic check` (nếu có script tương đương ở CI) không báo lệch.
- [ ] Seed giả lập nạp được: ít nhất 1 team, 1 user role `USER`, 1 user role `HR` cùng team (qua `team_members`), 1 user role `ADMIN`.
- [ ] API mẫu (`GET /portal/journeys` hoặc tương đương) chặn đúng: user role `USER` gọi → 403; HR đúng team gọi → 200; HR khác team gọi → 403; `ADMIN` luôn 200.
- [ ] Không có cột `users.primary_team_id` nào được thêm (đã bác bỏ ở mục 0) — nếu thấy xuất hiện trong diff, đó là sai lệch cần sửa lại.

## 5. Bàn giao cho P2

- P2 (state machine + API nhân viên) dùng thẳng `employee_tasks.status` đã tạo ở đây; thuật toán tính `READY` dựa trên `task_dependencies` (chỉ AND, P0A D8).
- Router mẫu ở mục 1.6 là khung để P2/P3 tiếp tục thêm endpoint thật, không cần dựng lại RBAC.
